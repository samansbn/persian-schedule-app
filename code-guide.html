01

Document shell and controls

The root document declares Persian as its language and uses right-to-left layout. The single page is arranged as three panels: input, review/edit, and preview/download. The latter panels begin hidden so the user sees only the current step. The fixed moon button toggles the app chrome; the top-right </> link opens this guide without taking space away from the mobile content.

The schedule selector keeps stable internal IDs (night, night-light, light-cards, purple-cards). English names are paired with Persian labels for clarity; changing visible names does not alter those IDs or rendering behavior.

Representative document structure
<html lang="fa" dir="rtl">
  ...
  <button id="themeToggle">🌙</button>
  <a class="code-guide-button" href="code-guide.html">&lt;/&gt;</a>
  <div id="inputPanel">...</div>
  <div id="editPanel" hidden>...</div>
  <div id="previewPanel" hidden>...</div>
</html>
  • fileInput reads a local HTML timetable.
  • pasteText accepts table markup or copied text.
  • The editor provides course, weekday, class start/end, location, instructor, exam date/time, and laboratory-exam fields.
  • The preview has a four-choice style selector and JPEG/HTML outputs.
02

App and schedule CSS

The first style block defines design tokens for the app itself: background, panel, border, text, accent, and input colors. The :root[data-theme="light"] rule replaces those values when the appearance toggle is light. Most controls refer to the variables, so the app shell changes together.

A second block, #scheduleVisualStyles, defines the generated schedule. Its .sched-page[data-style] selectors own the four output appearances. Each uses CSS variables for surface, ink, muted text, and accents, while day colors come from DAY_COLORS and remain independent of the selected theme’s primary color. The card themes also change row structure, rather than only swapping colors.

Theme token pattern
:root {
  --bg1: #0f0c29;
  --card: #1e1b4b;
  --text: #e2e8f0;
  --accent: #a5b4fc;
}
:root[data-theme="light"] {
  --bg1: #f5f3ff;
  --card: #ffffff;
  --text: #1e1b2e;
  --accent: #7c3aed;
}
.sched-page[data-style="light-cards"] .sched-row {
  display: flex;
  flex-direction: column;
}

When adding a schedule theme, update the selector, schedule CSS, and imageBackgroundForStyle() together. Keep the day-color map separate from theme accents.

03

App theme toggle

applyTheme(mode) sets or removes the root data-theme attribute and changes the button glyph. At startup the app safely reads scheduleAppTheme from local storage; read/write errors are caught so restricted browser storage does not prevent the app from starting. The click listener toggles light/dark and persists the choice. This preference affects the editor interface only; schedule appearance is selected separately.

Startup and persistence flow
var savedTheme = null;
try { savedTheme = localStorage.getItem("scheduleAppTheme"); } catch(e){}
applyTheme(savedTheme === "light" ? "light" : "dark");

themeBtn.addEventListener("click", function(){
  var next = document.documentElement.getAttribute("data-theme") === "light"
    ? "dark" : "light";
  applyTheme(next);
  try { localStorage.setItem("scheduleAppTheme", next); } catch(e){}
});
04

Constants and shared helpers

DAY_ORDER defines the canonical Persian weekday sequence; DAY_COLORS assigns a distinct color to each day. DAY_COMPACT, isDayLine(), and normalizeDay() accept spacing and spelling variants so the parser can recognize copied text consistently. Digit conversion helpers normalize Persian/Arabic numerals for comparisons, while output helpers convert digits back for display.

timeToMinutes() turns a clock string into a sortable numeric value. escapeHtml() encodes special characters before user-provided course names and other fields are inserted into markup. The shared state object stores the editable row records and schedule title; parsing, editor actions, and rendering all operate on that state.

05

HTML timetable parser

The HTML path uses the browser’s DOMParser, not a regular expression, to read markup as a document. findScheduleTable() identifies a likely timetable table. HEADER_MAP associates common Persian heading labels with internal record properties such as course, professor, day, time, exam date, and location.

buildColumnIndex() compares header cells with those aliases, allowing column order to change. getCellText() preserves line breaks from <br> elements and cleans the cell text. parseHtmlTableToRows() then maps each data row into the app’s record shape, normalizes day/digits, and extracts exam date and exam time separately. It skips unrelated columns and invalid/empty rows.

The parser’s transformation, simplified from its implementation
HTML string
  → DOMParser document
  → timetable table + recognized column indexes
  → one normalized class record per valid table row
  → editor state

The actual mapping and parsing implementation, including every alias and edge case, is included in the complete source below.

06

Pasted-text parser

If the input is plain text, linesFromRawText() splits it into useful lines/tabs and removes known header and administrative noise. The parser’s anchor expression recognizes weekdays and nearby date/time markers. parseLinesToRows() walks those lines, gathers course, class time, location, instructor, and exam values, and creates records. Since pasted text has no table structure, the algorithm uses neighboring lines and should be followed by a manual review.

parseWithLogic() chooses the HTML route when the pasted value contains table markup; otherwise it uses the text route. It updates status messaging, stores the extracted rows, and reveals the editor. This keeps both input formats converging on the same record shape and editing UI.

Input routing
if (looksLikeHtmlTable(rawText)) {
  rows = parseHtmlTableToRows(rawText);
} else {
  rows = parseLinesToRows(linesFromRawText(rawText));
}
state.rows = rows;
renderRows();
showEditPanel();
07

Editable class rows

blankRow() supplies a record with empty fields and default values. renderRows() turns every record in state.rows into a mobile-friendly card with labeled controls. When records change, the editor is rebuilt from state so what the user sees matches the data used for output.

Listeners are attached to the rows container rather than each generated control. The delegated input listener locates the record by its stable row index and writes changed values back to that record. The delegated click listener handles delete actions. “Add class” appends a blank record, while manual mode initializes the editor without parsing. The build button sorts for the preview without reordering the editing list.

Delegated editing pattern
rowsContainer.addEventListener("input", function(event){
  var field = event.target;
  var rowIndex = Number(field.dataset.index);
  var property = field.dataset.field;
  if (state.rows[rowIndex] && property) {
    state.rows[rowIndex][property] = field.value;
  }
});

The app escapes values rendered into HTML. Event wiring and the exact generated editor markup are shown in the complete source.

08

Sorting and schedule markup

sortedRows() creates a sorted view by weekday order and start time; the original editable array remains intact. examDisplayHtml() formats exam information as separately labeled date and time values, with a visible separator and spacing so they do not run together. Laboratory exams use the required Persian label امتحان آزمایشگاهی.

rowHtml() renders one class record with its day, course, time, location, instructor, and optional exam details. It escapes user values and applies the day color independently of the theme accent. buildScheduleFragment() wraps all rows in a title header and a .sched-page carrying the selected style ID. Preview rendering and standalone HTML export share this fragment builder, which keeps their content aligned.

One renderer, two destinations
function buildScheduleFragment(){
  var rows = sortedRows();
  var style = scheduleStyleSelect.value;
  return '<section class="sched-page" data-style="' + style + '">'
    + headerHtml(state.scheduleTitle)
    + rows.map(rowHtml).join("")
    + '</section>';
}
// Preview inserts this fragment; HTML export wraps the same fragment.
09

Standalone HTML and JPEG output

HTML
standaloneHtml() wraps the shared schedule fragment in a complete document and includes its schedule styles.
JPEG
html2canvas captures the rendered schedule element and converts the canvas to a downloadable JPEG.
Image settings
The capture uses an opaque style-matched background, 3× scale, and 98% JPEG quality.

The JPEG button is the primary action and appears above HTML download. imageBackgroundForStyle() selects a compatible canvas background for each theme. The export handler checks that html2canvas is available, shows status/errors, and triggers a .jpeg download. HTML export is separate and does not require canvas support. Both operations remain client-side.

10

Event wiring and the full source

The final script section connects the visible controls: file picker, pasted text, automatic extraction, manual editor, add/delete row, generate preview, theme selector, and downloads. Choosing a file clears pasted text, and typing clears the selected file so stale input cannot be parsed accidentally. The schedule-style listener refreshes the preview immediately when it is visible.

The execution path is: read input → parse records → review/edit → build preview → export. No timetable content is sent to a server.
