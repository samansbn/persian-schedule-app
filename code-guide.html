How the app works

A guided tour of index.html, from the page shell and Persian timetable parsers to schedule rendering and JPEG/HTML downloads.

Reading map. The app is deliberately a single HTML file. Its sections are separated with comments, and its output renderer is shared by the live preview and standalone HTML export. This page explains each section in source order.

01

Page shell and controls

The document starts with Persian language metadata and dir="rtl". The body contains three step panels: input, class review, and preview/export. The latter two begin hidden and are revealed as the user advances.

  • fileInput accepts local HTML files; the visible file button opens it.
  • pasteText accepts copied HTML or plain text.
  • The editor panel exposes row fields for course, weekday, class start/end, location, professor, exam date/time, and lab-exam status.
  • The preview panel contains the four-style selector and two output actions.

The small code-walkthrough link under the app title points to this page, so the documentation is available from the deployed app.

02

Design system and schedule themes

The first style block defines app-level CSS tokens for dark mode and overrides them for light mode using :root[data-theme="light"]. These variables style the input/editor panels and their controls.

A separate #scheduleVisualStyles block styles generated output independently from the app chrome. Each schedule wrapper carries data-style, and CSS selects one of four palettes/layouts: night, night-light, light-cards, and purple-cards. Weekday colors come from a fixed day-color map, so they remain separate from each theme accent.

If adding a theme, update the preview selector, its CSS, and the image background mapping together.

03

App appearance toggle

The floating button switches the app shell between light and dark. The chosen value is stored under scheduleAppTheme in localStorage. This setting is independent from the schedule-style selector, which controls the generated schedule.

04

Constants and helpers

DAY_ORDER controls weekday ordering, while DAY_COLORS maps normalized weekdays to their rail/card colors. normalizeDay() handles common Persian spelling/spacing variants; digit helpers convert between Persian and English digits for parsing and display. timeToMinutes() supports chronological sorting, and escapeHtml() protects user-provided values before markup insertion.

Shared state is a small object: state.rows contains class records, and state.scheduleTitle supplies the generated heading.

05

HTML table parser

parseHtmlTableToRows() parses the input with DOMParser and chooses a timetable table. HEADER_MAP maps recognized Persian column names to internal fields. buildColumnIndex() matches exact header labels first, then partial matches, so column order can vary and unrelated columns can be ignored.

Each data row becomes a normalized record with day, course, class times, location, professor, exam date/time, and lab-exam flag. Dates and times are extracted independently from their source cells.

06

Pasted-text parser

When input is not HTML, linesFromRawText() splits pasted lines/tabs and drops known header or administrative noise. parseLinesToRows() anchors on a recognized weekday, interprets nearby class/location/course/instructor lines, then scans following date/time values.

parseWithLogic() selects the HTML or plain-text path, stores extracted rows, reports a status, and opens the review panel. The heuristics are intentionally followed by an editing step because copied text may have ambiguous layout.

07

Review and edit state

blankRow() defines the empty record. renderRows() builds editable field controls from state.rows. Delegated input and click listeners update the matching record, change lab-exam state, delete a row, or append a new blank row.

The build action sorts a copy of the records; it does not rewrite their order in the editor. This keeps the user’s editing state independent from the chronological preview.

08

Sorting and schedule output

sortedRows() orders records by weekday and then start time. examDisplayHtml() displays exam date and time as separate labeled values, and uses the Persian امتحان آزمایشگاهی label for lab exams. rowHtml() renders each class once; the preview and downloadable HTML use this shared markup.

buildScheduleFragment() wraps those rows in the selected data-style and schedule title. When the style dropdown changes, the fragment is rebuilt immediately if the preview is open.

09

HTML and JPEG exports

HTML
Wrap the same schedule fragment in a standalone document and include schedule CSS.
JPEG
Capture only the styled schedule wrapper with html2canvas.
Opaque output
Provide a theme-matched background, render at 3×, and encode as JPEG at 98% quality.

The image button is the primary action and appears above the HTML download. The JPEG export uses a .jpeg filename and does not request transparency. `html2canvas` is loaded from cdnjs; if it fails to load, the app reports that image export is unavailable while the rest of the app remains usable.

10

Input event wiring

The final section connects file selection, pasted-text input, manual mode, automatic extraction, style changes, schedule building, and downloads. Selecting a file clears pasted text; entering text clears the pending file. These rules prevent the app from accidentally parsing stale input.

All parsing and schedule generation run in the browser. There is no application server or API endpoint.
